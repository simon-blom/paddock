# Phase 7 — isolated Qwen3.8 DeltaNet TP component gate

Status: two-Spark component decode/prefill/state parity passed and accepted as a clean milestone. The accepted paged-KV follow-on was separately committed as `f6a2cc1` before this work. This report does **not** claim production-model TP integration.

## Attribution and boundary

- Erik Bogado / ErikBPF `contrib/tp-10-deltanet-decode` (`8495d2d`) provides the prior complete-key-group split, quantized QKV/gate/output sharding, and whole-weight serial GPU oracle. `contrib/tp-11-deltanet-prefill` (`02ba232`) provides the native-span causal convolution/recurrent prefill and continuation gate. Both are MIT OR Apache-2.0 per the fork audit. Their same-process rank runner and copying are not transplanted: `qwen35/delta_tp.rs` uses the existing Paddock `Communicator`/NCCL two-process path.
- The TP=2 primitive lives only in `crates/paddock-engine/src/gpu_model/qwen35/delta_tp.rs`, exported by `mod.rs`; the two-node probe and independent whole-weight TP=1 oracle live in `examples/qwen35_delta_tp.rs`. No production `forward.rs`, scheduler execution protocol, KV, graphs, offload, speculation or performance paths were changed. Input is an already-normalized hidden vector/row span; upstream input norm and downstream residual remain in the unchanged serial model and are outside this isolated component comparison.
- For Qwen3.8 geometry 5120/16 key heads/48 value heads/128 state width/conv4, each rank owns eight whole key groups and the corresponding 24 value heads in three bands (`global_value_head % 16` maps to its key group). Checked GGUF whole-block gathering handles noncontiguous QKV output rows and `ssm_out` input blocks; each projection checks its own Q4_K/Q5_K/Q6_K type, alpha/beta are Q8_0, and F32 state vectors/conv weights are checked before upload. Rank-local convolution and recurrent state are allocated and reset independently: 1,634,304 bytes per rank (24×128×128 plus 3×5120 F32). Only final projected hidden rows are all-reduced; no per-token state exchange.
- Decode uses the existing one-token convolution, fused alpha/beta, GQA split, recurrent-v2 and gated RMSnorm GPU kernels. Prefill stages the previous local convolution window, executes a native causal-convolution span and recurrent-v2 over 2–64 tokens, retains local state for decode continuation, and reduces all output rows. This is a correctness gate, not a throughput implementation. Calls reject zero/oversized spans, input shape and rank/executor mismatch before state mutation.

The pre-existing `src/cuda.rs:83` unnecessary-cast warning remains; no unrelated file was edited.
- Two actual Sparks, same `Qwen3.8-27B-UD-Q4_K_M.gguf` model and `pd-cuda-sm120.so` pack used for Phase 6, final validation binary SHA256 `f14e895592ada8ee604782cb46c31c14c1ac757174748f8fa8947adb35a8814e` identical on both nodes. Both processes exited 0 with matching maximum output errors per step. Layer 0 (Q5_K projections) and layer 1 (mixed Q4_K QKV/gate and Q6_K output) independently passed all-element GPU parity against their own whole-weight, one-token serial oracles at `abs(tp - oracle) <= 1e-3 + 1e-3*abs(oracle)`: eight initial decode steps; warm prefill spans of 2, 7, 31 and 64 rows; decode after each prefill; zero-state nine-row prefill; exact first-step output replay after reset. Rank-local recurrent state (every element for each owned value head) and all conv window elements were checked after every decode/span/continuation/reset on **both** ranks against the serial oracle, including the step-115 continuation. Maximum observed output absolute difference was 0.000031 for layer 0 and 0.000004 for layer 1; state checks stayed within the same bound. Invalid sizes (5119-element decode, zero-row prefill, 65-row prefill) were rejected without mutating state.

## Scope after this gate

Two isolated DeltaNet layers, synthetic normalized input, one active sequence, bounded 64-row spans, F32 recurrent state, and the pinned GGUF were exercised. This is not an end-to-end Qwen3.8 generation test, all-layer proof, production TP=2 model wiring, multi-sequence state lifecycle, or a performance claim. The serial oracle holds complete weights only for the probe; the TP component holds rank-local weights and state. TP=1 production forward was untouched, and the oracle uses identical F32 recurrent geometry and epsilon from model metadata. Integration belongs to the later plan phase, not this milestone.
