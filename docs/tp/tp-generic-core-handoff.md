## Current module boundaries

`crates/paddock-engine/src/lib.rs` declares engine-root `tp` behind `cuda`; `gpu_model/mod.rs` no longer owns the generic subtree. `crates/paddock-engine/src/tp/` has seven files:

- `mod.rs`: `TpTopology`, `TpLinearMode`, topology errors and module visibility.
- `attention.rs`: `GqaPartition`, `AttentionTpWeights`, `PagedAttentionTable`, `PagedKvBatch`, `prefill_paged`, `decode_paged`, output reduction and host geometry tests.
- `ffn.rs`: generic sharded dense SwiGLU rank and row-batched prefill.
- `prefill.rs`: projection scratch/staging, backend contract and quant layout helpers.
- `cache.rs`: `MirroredKv` operations, sequenced snapshots, table generations, prefix admission/publication/reuse.
- `state.rs`: `TpCheckpointState`, `CheckpointOp`, preflighted transfer.
- `control.rs`: `WorkerSet` control fan-out/ACK barrier.

Non-root dependencies remain in `gpu/distributed.rs` (collective compute/communication fences), `paddock-models` tensor slicing, `paddock-dist` bootstrap/protocol, and the engine's normal GPU kernel dispatch. Qwen-side adapters are `gpu_model/qwen35/{gqa_tp,ffn_tp,tp_prefill_backend,tp_span,tp_model,tp_kv,delta_tp,tp_serve,tp_graph}.rs`; `ops.rs::prefill_attn` still serves other Qwen paths, including normal TP=1. Do not delete it simply because TP span now calls generic `prefill_paged`.

## Latest changes and review-sensitive invariants

- `a3846d4`: relocation only, no compatibility alias. Imports and plan paths updated. Its first engine `--all-targets` check exposed stale examples, subsequently fixed by `861e67e`; current all-targets check passes.
- `d4b2ceb`: Qwen `gqa_tp.rs::paged_prefill_policy` still decides row/dtype/geometry eligibility. For `rows <= 24`, both fast choices are off. Above 24 rows, the F16-named kernel requires 256-wide heads, a 64-aligned `max_ctx`, and `ops::pf_attn_dtype_ok`; tiled requires head dimension 128 or 256. Generic `attention.rs::prefill_paged` checks kernel availability in priority order F16, tiled, paged decode fallback. Its `F16` name is a kernel family, not proof the KV cache dtype must be F16; Qwen's dtype guard governs eligibility. The same table, slot, positions, scale and live rows go to each branch. No split scratch is passed on this prefill path. Qwen's Q/gate projection, normalization, M-RoPE and post-attention sigmoid gate remain outside generic dispatch. Normal TP=1 `ops::prefill_attn` was not changed.
- Decode keeps Qwen's measured split-count policy and its special override. Generic `decode_paged` owns single-pass vs split partial+combine, validates scratch and kernel presence, and requires a split count stable across graph replays. A one-row Qwen TC5 override must not be accidentally routed through the generic split path. Do not replace model policy with a hard-coded TP=2/default split count.
- `PagedKvBatch` uses the same staged block table for K, V and attention; it preflights **both** payloads and metadata before either append. `PagedAttentionTable` validates logical coverage on every decode but uploads only changed slot mappings. `SpanGqa::staged` shares per-span block table/positions/slot/M-RoPE metadata across GQA layers, restaging when slot/position/rows change; validation covers the span's last logical position.
- All ranks follow the same collective order. In span prefill, reduce only the `rows * hidden` LIVE prefix, with `after_compute -> all_reduce -> before_compute` fences. The profiling branch currently performs an equivalent collective with CUDA timing events: when removing it, retain the normal uninstrumented collective and fences. Rank 0 authorizes mirrored logical KV events; workers replay/check before GPU use. Slot release/reset must drain in-flight GPU/worker operations before reuse.
