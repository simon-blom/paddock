# Phase 10 progress — two-slot eager continuous-batching integration

Status: two-Spark max-batch=2 eager serving and a two-slot full-vocabulary eager oracle have passed; this is still **not** a Phase 10 async/overlap acceptance report.

Rank 0 retains the existing engine scheduler, admission, cancellation, and sampler. A `--max-batch 2` TP=2 run elects the ordinary batched loop rather than the Phase 9 serial loop. The scheduler's dense high-water rows are translated to ordered active slot/token/position rows; holes are omitted and logits are returned at the original slot indices. Prefill uses the generator's per-prompt default (eager token steps), and each decode row runs the accepted whole-model rank-local TP primitives in the same order on both ranks. This is continuous admission and batched *scheduler* execution, not a fused GPU batch or nonblocking forward.

Rank 0 authorizes logical paged-KV Ensure/Release/Flush events; rank 1 mirrors and checks sequence, slot order, position and resulting KV snapshot before its next collective. A slot release resets its DeltaNet recurrent/conv state without touching surviving slots; full reset clears every slot. Each GQA layer has slot-indexed block tables and rank-local payload. Both ranks retain Phase 9 pinned checkpoint/pack/context bootstrap, FP16 KV, eager kernels and two-rank NCCL collectives. TP graph capture, speculation, vision, offload and companion models remain excluded.

## Live scheduler pipe acceptance

The scheduler bounds fixed-context lookahead against `max_ctx`, including completed members still executing as dummies. `TpGenerator::decode_pipe_context_limit()` supplies the capacity; a host test covers limit, hole, and dummy positions. Unenqueued plans peek categorical uniforms; successful enqueue commits a draw only for a request surviving the preceding token, so dummy overshoot and abandoned arrivals do not advance a cancelled/completed seed. TP prefill remains after pipe drain because the rank owns one model/stream/scratch lane; the short-admission-before-drain shortcut now requires `supports_overlap`.

The initial two-Spark HTTP pipe probe (release runner SHA-256 `8fe0aef3324c92fa8c52b14df8d8196d3b852f35b6a821fcc3030748290ed57d`) compared context exhaustion, a short completed dummy beside a surviving long slot, streamed cancellation, reuse and arrival against sampled eager. Both ranks exited 0, and response text, finish and usage matched. This was an HTTP-only gate, not token-ID proof.

The subsequent live token-ID/RNG gate used a temporary per-request scheduler trace (removed after validation) with explicit `top_k=0`, `top_p=1`, `min_p=0` to exercise device categorical rather than the checkpoint's host-truncation defaults. ## Overlap audit and implementation boundary

The detailed dependency-ordered design and acceptance gates are in [phase10-overlap-boundary.md](phase10-overlap-boundary.md). This is a clean design boundary, not an implemented overlap lane.

The current model has one compute stream and one `token`/`x`/`xn`/`logits`/sampling-parameter scratch set (`tp_model.rs:56-76,216-235,445-545`); the two ID planes protect only feedback. The layer paths also reuse their own scratch: FFN gate/up/partial/reduced (`ffn_tp.rs:36-46,109-127`), GQA projections/metadata/block table (`gqa_tp.rs:92-113,308-508`), and DeltaNet intermediates plus slot-swapped recurrent/conv state (`delta_tp.rs:200-259,435-456,468-629`). A second compute stream without distinct lane scratch would race even on disjoint slots. The large-vocabulary CUDA sampler explicitly uses device-global `pd_sr_*` arrays across its A/B/C kernels (`packs/cuda/src/deltanet/stage2_sample.cuh:2230-2249,2439-2455`); concurrent rank-0 sampler calls need caller-owned scratch or an explicit cross-stream sample fence. NCCL already has its own stream with compute/NCCL event ordering (`gpu/distributed.rs:108-182`), but those fences currently refer only to the model's one compute stream.

The TP prefill implementation is a serial one-token `run_rows` loop with full-logit readback on every prompt token (`tp_serve.rs:281-293,505-520`); no TP unified-span/chunked-prefill trait implementation exists. The worker and coordinator reject non-pipe commands until drain (`tp_serve.rs:671-674,948-955`), and the existing TP wire messages have no independent prefill flight/lane identity. The scheduler requires a unified span and arbitrary-slot pipe membership together for its overlap branch (`service.rs:3781-3873`). The minimum viable path is therefore: separate per-lane backbone and per-layer scratch while sharing immutable weights and slot-owned KV/state; implement a bounded TP prefill span and final-row finisher; extend the rank-0-authorized protocol for independent lane/flight identities and mirrored KV events while preserving Prepared-before-collectives and deferred Ready; add explicit compute/NCCL/cross-lane/sample fences and join both ranks before release/reset/reuse; then prove simultaneous in-flight work and token/RNG/logit parity on both GPUs across cancellation, page crossing and slot reuse. Do not enable `supports_overlap` on host-level interleaving alone.
