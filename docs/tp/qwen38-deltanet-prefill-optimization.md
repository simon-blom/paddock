# Qwen3.8 TP=2 DeltaNet prefill: measured alpha/beta batching

2026-09-28; starting HEAD `c3c7971` (`review/qwen38-tp2-final`). The production default span cap remains 64; the matching long-prompt TP2 comparison below explicitly sets `PADDOCK_TP_SPAN_CAP=192`. Profiling remains opt-in with `PADDOCK_TP_PREFILL_PROFILE=1`; timing-enabled CUDA events and per-span synchronization make its stage times diagnostic, not headline wall time.

## Root cause and decision

The broad 192-row TP2 `conv/split/gate preparation` bucket in `qwen38-deltanet-internal-profile.md` measured 13.380 s versus 1.759 s on TP1. A further pair of opt-in CUDA-event boundaries within `DeltaTpRank::run` separated the rank-local per-row alpha/beta loop from conv/split. On the *same* 22,130-token TP2 request, 13.108 s was the loop (one 5,120-element row copy, fused alpha/beta launch, and two tiny output copies per token); only 0.607 s was the conv-window copies, convolution, and QKV split/norm. The recurrent kernel was 1.011 s. Thus rewriting the recurrence or conv kernel first would attack the wrong stage. The existing `q8_0_gemm_repacked_x2` batched repacked-Q8 projection and `delta_gate` accept the 24 local value heads and full row count without a pack/ABI change. The existing fused one-row gate remains on decode and one-row prefill; multi-row prefill now projects/gates the entire live span once, directly into rank-local gate/beta buffers. The old multi-row loop remains for the non-prefill path. No state is gathered, and recurrent/conv state ownership, snapshots, window continuation, reduction order, and decode dispatch are unchanged. Extra scratch is two `span_cap * 24` f32 planes per layer.

A GPU test compares batched gate and beta against the original per-row fused kernel bit-for-bit for local geometry (input 5120, 24 heads) and rows 2, 64, 128, 192: zero differing f32 bits in all cases. The fallback pair of individual batched GEMMs is only used if the existing x2 kernel slot is absent; the tested pack used x2.

## Correctness checks and limits

- `cargo test -p paddock-engine --lib`: 518 passed; `cargo test -p paddock-dist`: 6 unit + 22 bootstrap passed.
- `PADDOCK_PACK=... cargo test -p paddock-engine --test gpu_delta_ops_parity --test gpu_delta_net_parity --test gpu_delta_mixer_parity`: 12 passed (one optional heavy speed gate printed SKIP inside its passing test). The new TP-local gate test passed at 2/64/128/192 rows with bitwise-identical gate/beta. Recurrence/conv/mixer CPU-reference checks passed; recurrence itself was not modified.
- TP2 cold chat at caps 64 and 192: HTTP 200, 22,130 tokens, 64-token outputs exactly matching the corresponding old binary; decode followed each prefill. Two simultaneous TP2 requests (2963/3086 prompt tokens) used both slots, returned HTTP 200 and 16 completion tokens each; rank-0 logged a slot-1 Mixed span and checkpoint cuts. This is serving-path smoke, not an exact-logit multi-slot oracle.
- Identical-request prefix-cache hit at cap 192 resumed 22,128 tokens and computed 2; it returned HTTP 200 on both binaries. A cold/hit full-text mismatch near the *end* of the 64-token completion occurred on both baseline and optimized binaries, and a second hit sometimes matched cold again. Therefore strict cold/hit byte identity is **not established**, even though the state ownership code was untouched and the numerical gate test is exact. This pre-existing nondeterminism deserves an isolated deterministic state/logit oracle before claiming strict resume parity. Divergent-tail, cancellation, and explicit state-buffer equality were not exercised in this pass.
- `cargo check -p paddock-engine`, release runner build, `cargo clippy -p paddock-engine --lib --tests`, and `git diff --check` passed; clippy retained the pre-existing `cuda.rs` same-type cast warning.

## Next opportunities / cap decision

The recurrent kernel is about 1 s on both TP1 and TP2 here; switching TP2 to chunked recurrence at rows <=192 would change accumulation order without addressing the measured cause. Defer until a same-shape, standalone A/B proves speed and a state/parity oracle passes. Conv/split is now ~0.61 s: the existing fused conv/QKV kernel may be reusable on an extended window, but its fresh-prompt offset contract zeros preceding rows; blindly pointing it at a nonzero slot window would corrupt continuation. Do not change it without a window-aware, row-aligned adaptation and an exact state-continuation test. The >64 cap is already supported and measured: 192 beats 64 substantially even after this fix, but the default stays 64 pending a full resumed-prefix/multi-slot correctness sweep at 192. Use the explicit `PADDOCK_TP_SPAN_CAP=192` for the measured faster lane. Remaining DeltaNet time at cap 192 is approximately 5.8 s local substage sum plus ~1.9 s NCCL in the diagnostic; projection kernels, collective costs, and the separate TP1 7.7-s baseline are future work, not benefits claimed here.
