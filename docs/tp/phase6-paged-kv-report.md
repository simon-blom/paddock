# Phase 6 follow-on — mirrored paged KV GQA component gate

Status: isolated two-Spark component parity passed and accepted as a milestone. Phase 6 (`5b95cbf`) remains the baseline. This follow-on completes its deferred paged-KV probe, **not** the plan's Phase 7 DeltaNet work. Per the current request, no production qwen35 forward, scheduler execution protocol, DeltaNet, graphs, offload or speculation was changed.

## Boundary and attribution

- `qwen35/tp_kv.rs` owns CPU-only `MirroredKv`: rank 0 authorizes ordered logical `Ensure`, `Release`, `Publish`, `Reuse`, `Reset` and `Flush` operations using the existing `KvPool`, `BlockTable` and `PagedRadix`. A rank-1 mirror replays each operation and compares the complete block-table/refcount/free snapshot before GPU execution; missing/out-of-order events fail. Failed growth is pre-checked to avoid partially applying a failed event. `Reset` releases slots but preserves cached prefixes; `Flush` also evicts cached pages and returns all blocks. `Publish` assumes the caller has finished writing all full pages it publishes; the probe synchronizes first. There is no production wire protocol here.
- `qwen35/gqa_tp.rs` adds a paged variant of the isolated Phase 6 rank-local GQA primitive. It validates the full live read prefix against `MirroredKv` before staging the mirrored row-major table on the local device, then executes the existing `kv_append_batch_paged` and `attn_decode_batch_paged` GPU kernels, with each rank holding K/V for only its own two KV heads. It retains the old contiguous method separately. Per physical 16-token block, each rank charges 32,768 bytes K+V at f16; four-block pool payload is 131,072 bytes per rank (versus 262,144 for all four KV heads). This is component accounting; the production `Demand`/`Plan` model has **not** been changed or validated for TP.
- The example's optional `paged` mode uses a probe-only length-prefixed JSON exchange on the existing bootstrap TCP connection for rank-0 events, while NCCL remains the only tensor communication. It runs a 17-step one-token sequence across a page boundary, publishes the first full page, frees slot 0, adopts that page in slot 1, replays position 16 without rewriting the prefix, then flushes and checks exact step-0 replay after physical block recycling. A rank-0 full-weight contiguous GPU oracle independently computes every output for comparison.
- The complete-GQA-group split and same-weight oracle derive from Erik Bogado / ErikBPF `contrib/tp-09-attention-block` (`afedfdd`), MIT OR Apache-2.0, as attributed in Phase 6 and `gqa_tp.rs`. The mirrored logical lifecycle adapts Paddock's own existing `kv_pool`/`paged_radix` abstractions; it does not import the fork's same-process transfers.

## Limits before integration

The probe is one GQA layer, two slots, f16 KV, 32-token limit, one-token decode, and four physical pages. The rank-0 event exchange and full-state snapshot are intentionally test scaffolding, not a production scheduler protocol. No multi-layer KV budgeting, cancellation/failure recovery across a live worker, partial-page CoW, concurrent batches, or full qwen35 model parity was exercised. The full-weight oracle exists only on rank 0 for validation. Keep the TP primitive isolated until those integration gates have explicit ownership and tests. The plan's Phase 7 names DeltaNet; this follow-on does not claim Phase 7 complete.
